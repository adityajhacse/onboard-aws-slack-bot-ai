================================================================================
MCP client: src/mcp_client.py (LocalMcpClient)
================================================================================

Purpose
-------
In-process helper that starts the local DET MCP server as a **child process**
(stdio), connects with the official MCP Python **ClientSession** over stdio,
initializes the session, invokes **one tool** by name, tears the connection
down, and returns a **plain dict** parsed from the tool result.

This is a thin wrapper for callers (e.g. ai_orchestrator) that need to run
mcp_server.py tools without implementing MCP framing themselves.

This file does **not** list resources, list tools, or subscribe to MCP
notifications — it only supports **tools/call** for a single invocation per
`call_tool()` use.

================================================================================
Class: LocalMcpClient
================================================================================

Constructor
-----------
LocalMcpClient(server_path: Path | None = None)

  server_path
    Path to the server entry script. Default: same directory as this file,
    file named "mcp_server.py" (Path(__file__).with_name("mcp_server.py")).

Public method
-------------
call_tool(
    name: str,
    arguments: dict[str, Any] | None = None,
    *,
    extra_env: dict[str, str] | None = None,
) -> dict[str, Any]

  Synchronous API. Internally runs asyncio.run(_call_tool(...)) so each call
  spins up a fresh event loop for the async MCP client lifecycle.

  name
    MCP tool name exactly as registered on the server (e.g. the @mcp.tool
    function names in mcp_server.py).

  arguments
    JSON-serializable dict passed as the tool's input object. Defaults to {}.

  extra_env
    Key/value pairs merged **on top of** os.environ for the **child** process
    only (parent os.environ is copied first, then these overrides apply).
    Use this to pass secrets or flags (e.g. GITHUB_TOKEN, DET_DRY_RUN,
    DET_MCP_WRITE_TOKEN) without mutating the parent environment.

  Returns
    A dict produced by _decode_tool_result() — see below. Not the raw MCP
    SDK object.

================================================================================
Async implementation: _call_tool (internal)
================================================================================

Flow:
  1) Lazy-import mcp.ClientSession, StdioServerParameters, stdio_client.
     On ImportError: raises RuntimeError with pip install hint.
  2) child_env = {**os.environ, **extra_env}
  3) StdioServerParameters(
         command=sys.executable,
         args=[str(self.server_path)],
         env=child_env,
     )
     So the server is started as: same Python interpreter, script path from
     server_path (typically mcp_server.py). That script's __main__ uses
     mcp.run(transport="stdio") as defined in mcp_server.py.
  4) async with stdio_client(params) as (read_stream, write_stream)
  5) async with ClientSession(read_stream, write_stream) as session
  6) await session.initialize()
  7) result = await session.call_tool(name, arguments)
  8) return _decode_tool_result(result)

Each call_tool() therefore starts a **new** server subprocess and closes it
when the async block exits. There is no connection pooling or long-lived client.

================================================================================
Result shaping: _decode_tool_result(result) -> dict
================================================================================

Normalizes the MCP SDK tool result into a dict for application code.

  1) dumped = _model_dump(result)
       - If result has model_dump (Pydantic-style), use model_dump(by_alias=True).
       - Else if result is dict, use as-is.
       - Else return {}.

  2) is_error from dumped["isError"] or dumped["is_error"] (bool).

  3) Prefer structured payload if present (any of):
       structuredContent | structured_content | data
     If that value is a dict, return it immediately.

  4) Otherwise gather text from result.content (list of parts): each part may
     be dict with "text" or object with .text attribute; concatenate non-empty
     strings into texts[].

  5) If texts is empty: return dumped if dict else {"result": dumped}.

  6) If is_error: return {"status": "error", "message": joined texts}.

  7) If exactly one text blob: try json.loads(texts[0]); if dict return it,
     if other JSON type return {"result": parsed}; on JSONDecodeError return
     {"text": texts[0]}.

  8) If multiple text blobs: return {"content": texts}.

This matches typical FastMCP tool returns (JSON dict in structured content or
single JSON string in text content) and surfaces tool/runtime errors as
{"status": "error", "message": "..."}.

================================================================================
Helper: _model_dump(value) -> dict
================================================================================

Used only by _decode_tool_result. Coerces SDK objects to dict when possible;
otherwise returns {} for unknown shapes (downstream decode may still use
result.content via getattr on original result in step 4 — note that content
is read from `result`, not only from dumped).

================================================================================
Dependencies
================================================================================

Requires the `mcp` package (MCP Python SDK / client stack). If import fails,
RuntimeError points to: pip install -r requirements.txt in the active venv.

The child process needs whatever mcp_server.py needs (fastmcp, det_intake,
github_api, hcp_terraform, etc.).

================================================================================
Environment and secrets
================================================================================

No environment variables are read directly by mcp_client.py except:

  - os.environ is copied into the child for every call (unless keys are only
    in extra_env — still merged from parent os.environ first).

Typical pattern: pass GITHUB_TOKEN, DET_MCP_WRITE_TOKEN, DET_DRY_RUN, and
Slack-related data via **arguments** to the tool and/or **extra_env** so the
server subprocess sees the same configuration as a manually run server.

================================================================================
What this file does NOT do
================================================================================

- No MCP resources/read (det://... URIs are not fetched by this client).
- No tools/list or session.list_tools in this module.
- No HTTP/SSE transport — stdio child only.
- No persistent session across multiple tool calls (each call_tool = new
  process + new MCP session).

For server-side tool and resource definitions, see docs/mcpserver.txt.
